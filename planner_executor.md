# 📝 Agentic Design Pattern – Planner-Executor

The **Planner-Executor** design pattern is a powerful multi-agent workflow where complex tasks are broken down into manageable sub-tasks before execution. This separation of concerns allows the AI to "think before it acts," significantly improving accuracy and depth for complex requests.

## 🏗️ Architecture

```
                    ┌─────────────────────┐
                    │    User Request     │
                    └────────┬────────────┘
                             │
                             ▼
                ┌────────────────────────────┐
                │          Planner           │
                │ (Breaks task into steps)   │
                └────────────┬───────────────┘
                             │
                             ▼
                ┌────────────────────────────┐
                │          Executor          │
                │ (Executes steps sequentially│
                └────────────┬───────────────┘
                             │
                             ▼
                    ┌─────────────────────┐
                    │    Final Output     │
                    └─────────────────────┘
```

## 🧠 How It Works

This pattern utilizes two distinct agents working in sequence:

### 1. The Planner Agent
- **Role:** Analyzes the high-level task and decomposes it into a structured, step-by-step plan.
- **Input:** A complex user task (e.g., "Create a simple 3-step plan for launching an AI chatbot product").
- **Output:** A list of discrete, actionable steps.
- **Implementation Detail:** In our code, the Planner uses Few-Shot prompting to ensure the LLM strictly formats its output as a bulleted list without unnecessary conversational filler.

### 2. The Executor Agent
- **Role:** Iterates through the generated plan and performs the actual work for each step.
- **Input:** The list of steps generated by the Planner.
- **Output:** The aggregated results of executing each step.
- **Implementation Detail:** The Executor loops over the plan array, calling the LLM independently for each step to maintain focus, and concatenates the results into a final `output` string.

## 🗂️ State Management (`PlanState`)

The LangGraph state for this workflow tracks three key pieces of information as it flows through the graph:

```python
from typing import TypedDict, List

class PlanState(TypedDict):
    task: str           # The original request from the user
    plan: List[str]     # The steps generated by the Planner
    output: str         # The final aggregated result from the Executor
```

## 🚀 Why Use This Pattern?

- **Reduced Hallucinations:** By forcing the model to explicitly plan its actions, it is less likely to skip important details.
- **Modularity:** You can easily swap out the Executor agent. For example, instead of just using an LLM to generate text, the Executor could use tools (like web search or a code interpreter) to complete each step.
- **Traceability:** You can surface the generated plan to the user in a UI so they know exactly *how* the AI intends to solve their problem before the heavy computation begins.

## 💻 Example Usage

When given the prompt: *"Create a simple 3-step plan for launching an AI chatbot product."*

1. **Planner generates:**
   - Define the target audience and core features.
   - Build and test the MVP.
   - Execute a marketing launch campaign.

2. **Executor processes each step:**
   - Generates a paragraph on defining the audience.
   - Generates a paragraph on MVP testing.
   - Generates a paragraph on the marketing launch.
   
3. **Result:** A comprehensive, well-structured response that addresses the original prompt thoroughly.
